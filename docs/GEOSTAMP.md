# FeTreeGO! — 위치 기반 스탬프 수집 시스템

> 내부 시스템명: GeoStamp (위치 판정 모듈)

## 철학

인터넷이 인간을 화면에 가두는 블랙홀이 되기 전, 사람들은 바깥에서 시간을 보내고 직접 만들었다. FeTreeGO!는 그 방향을 뒤집는 기능 — 디지털이 사람을 현실 세계로 내보내는 구조.

포켓몬 고에서 핵심만 취한다: **물리적 이동이 디지털 보상을 해제한다.**

유튜브: "더 보세요" → 화면에 가둠.
FeTreeOS: "나가서 찍어오세요" → 현실로 내보냄.

## 핵심 구조

### 흐름

1. 크리에이터가 실제 장소를 방문
2. 주변 환경 요소(나뭇잎, 벽 질감, 그림자, 간판, 돌, 이끼 등)를 소재로 콜라주 기반 크리쳐/구조물 제작
3. 해당 장소에 스탬프 포인트 등록 (좌표 + 사진 + 크리쳐)
4. 유저가 같은 장소에 물리적으로 가서 GPS 판정 → 스탬프 잠금 해제
5. 획득한 크리쳐/구조물은 FeTreeOS 내 도감/프로필에 수집

### 콘텐츠의 특성

- 크리쳐가 그 장소의 환경으로 만들어짐 → "거기 가야만 의미가 통하는" 콘텐츠
- AI 생성이 아니라 인간이 직접 빚은 것 — 프로젝트 철학 그 자체
- 포켓몬 고는 기존 캐릭터를 위치에 붙인 것이지만, 이건 **장소가 캐릭터를 만드는 구조** (역방향)
- 수집 욕구 + 탐험 동기 + 작품성이 동시에 작동

## 기술 설계

### GPS — 안전한 일시적 사용

```javascript
navigator.geolocation.getCurrentPosition(
  (position) => {
    const { latitude, longitude } = position.coords;
    // 메모리에서만 사용, 서버 전송 없음
    // 클라이언트에서 범위 판정만 수행
  },
  (error) => {
    // 사용자 거부 시 — 정상 동작, 강제하지 않음
  },
  {
    enableHighAccuracy: false,  // 대략적 위치면 충분
    timeout: 5000,
    maximumAge: 300000  // 5분간 캐시 (GPS 재호출 방지)
  }
);
```

### 프라이버시 원칙

- 서버에 유저 좌표 저장하지 않음 — 클라이언트 메모리에서만 처리
- 세션 종료 시 폐기 — 탭 닫으면 끝
- 정밀도를 낮춤 — 동네 수준(반경 500m 정도)이면 충분
- 지속 추적(watchPosition) 대신 1회 스냅샷(getCurrentPosition) 사용
- UX에 명시: "위치는 저장되지 않으며, 스탬프 판정에만 일시적으로 사용됩니다"

### 판정 로직

```javascript
function isWithinRange(userPos, stampPos, radiusMeters = 500) {
  const R = 6371000; // 지구 반경 (m)
  const dLat = (stampPos.lat - userPos.lat) * Math.PI / 180;
  const dLon = (stampPos.lng - userPos.lng) * Math.PI / 180;
  const a = Math.sin(dLat/2) ** 2 +
            Math.cos(userPos.lat * Math.PI / 180) *
            Math.cos(stampPos.lat * Math.PI / 180) *
            Math.sin(dLon/2) ** 2;
  const distance = R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1-a));
  return distance <= radiusMeters;
}
```

### 위조 방지 — 저수준 인증 + 휴리스틱

#### 설계 사상

**거기를 갔다오지 않고서는 할 수 없는 것을 요구한다.**

GPS를 기술적으로 완벽히 방어하는 것이 목적이 아니다. 콘텐츠 구조 자체가 방어 장치가 되는 설계:
- 콜라주 크리쳐의 원재료를 현장에서 직접 확인하는 행위
- 커뮤니티 약도에 현장에서만 알 수 있는 정보를 기여하는 행위
- 스트리트뷰에는 없는 현장 디테일 (계절 변화, 뒷면, 냄새, 소리, 시점에 따른 차이)

스푸핑으로 GPS를 속여도, 현장 경험 없이는 의미 있는 참여 자체가 불가능한 구조. 기술적 차단이 아닌 "속이는 데 드는 노력 > 직접 가는 노력"으로 물리적 무의미를 달성한다.

성능 부담을 유저에게 전가하면서까지 고수준 인증을 강제하지 않는다.

#### 인증 구조 — 병행 트랙

모든 스탬프 페이지에 두 트랙이 나란히 존재한다. 특정 유저를 위한 별도 경로가 아니라, 모두에게 열린 두 가지 방법.

**트랙 A: 이동 인증 (현장)**

GPS = 탐색 가이드 (인증 수단이 아님):
- 반경 내 진입 시 힌트 해제 — "이 근처에 뭔가 있다"를 알려주는 탐색 도구
- 스탬프의 존재와 방향을 안내하는 역할
- GPS만으로 스탬프가 해제되지 않음

현장 전용 인증 = 실제 열쇠:
- 거기 가서만 볼 수 있는 것, 확인할 수 있는 것을 요구
- 조형물/환경 요소 기반 — 스트리트뷰로는 알 수 없는 디테일
- 현장 경험 없이는 답할 수 없는 구조

보조 휴리스틱 (사후 검증):
- EXIF 타임스탬프: 촬영 시점이 판정 요청 시점과 근접한가
- 파일 특성: 카메라 촬영 원본인가 (해상도, 파일 크기, 메타데이터 존재 여부)
- 서버 전송 없음: 사진은 클라이언트에서 메타데이터만 확인 후 폐기

**트랙 B: 대체 인증 (디지털 탐험)**

크리에이터가 직접 걸은 경로를 비주얼 노벨 + 미니게임으로 구성:
- 각 스테이지가 unlisted 링크로 연쇄 — 미니게임 돌파 시 다음 장소 해제
- 이동자의 "걷기"를 플레이어의 미니게임 내 물리적 행위(조작, 탐색, 퍼즐)로 치환
- 건너뛰기 불가 — 연쇄 구조가 순서를 강제
- 약도가 미완성 상태로 제공 → 스테이지 진행 + 퀴즈로 약도를 완성
- 완주 시 약도 로그 참여자로 등록 — 이동 인증과 동일한 도착점

**두 트랙의 관계:**
- "배려"가 아니라 "옵션" — 이동 가능한 사람도 대체를 택할 수 있음
- 보상은 동일, 도착점(약도 참여자)도 동일
- 형태만 다를 뿐, 성의 없이는 어느 쪽도 도달 못 하는 구조

#### 비정상 패턴 감지 (휴리스틱)

- 물리적 불가능: 짧은 시간 내 먼 거리의 스탬프 연속 해제 → 플래그
- 반복 패턴: 동일 시간대에 매일 같은 스탬프 해제 시도 → 의심
- 대량 수집: 비정상적 속도로 다수 스탬프 연속 해제 → 속도 제한

플래그된 계정은 즉시 제재가 아닌 내부 검토 대상. 오탐 가능성을 고려한 관대한 기준.

#### 고수준 인증 (선택적 확장 — 성능 부담 없을 때만)

필요성이 입증되고, 기기 성능이 충분한 환경에서만 선택적으로 도입:

- ORB 특징점 매칭 (OpenCV.js WASM, ~2-3MB) — 조형물 사진 정밀 비교
- pHash/dHash — 지각적 해시로 유사도 판정
- NetVLAD/CosPlace — 서버 사이드 딥러닝 장소 인식 (최후순위)

이들은 "기본 인증으로 부족한 상황이 실제로 발생할 때" 도입을 검토하는 옵션이지, 초기 설계의 필수 요소가 아니다.

#### 현장 인증의 성격

- 누가 봐도 알 수 있는 것 — 난해하거나 전문 지식을 요구하지 않음
- 팍팍하지 않은 경험 — 인증이 아니라 탐험의 일부로 느껴지는 수준
- 그런 것을 찾아서 설계하는 것이 크리에이터의 역할

#### 스탬프 생명주기 관리 (규모 확장 대비)

프로젝트 규모가 커지면 현장 환경은 크리에이터 모르게 변한다:
- 조형물 철거/변경
- 계절 변화로 인증 답이 달라짐
- 주변 환경 변화 (공사, 폐업, 재개발)

**커뮤니티 제보 시스템:**
- 제보는 자유 원칙 — 누구든, 언제든
- 개선은 신속하게 대응
- 제보 포맷 (감정적이지 않고, 직접 대응에 용이한 구조):
  - 어디가: 스탬프 ID 또는 장소명
  - 어떻게 달라졌는가: 변경 내용 (철거됨 / 형태 변경 / 접근 불가 / 공사 중 등)
  - 사진 첨부 (선택): 현재 상태를 보여주는 증거
- 제보 접수 시 스탬프 일시 비활성화 → 크리에이터 확인 → 갱신 또는 폐기

**정기 갱신:**
- 일정 기간 경과 시 재검증 요청 (크리에이터 본인 or 커뮤니티 대리 확인)
- 장기 미갱신 스탬프는 "미확인" 라벨 표시

**관리자 위임 (확장 시):**
- 지역별 모더레이터가 해당 지역 스탬프 상태를 관리
- 크리에이터 1인이 전국을 감당할 수 없는 시점에 도입

**GPS 보조 승격 (비상시):**
- 현장 전용 인증이 무효화된 스탬프(조형물 소멸 등)에 대해 임시로 GPS 기반 인증 허용
- 대체 인증 요소가 마련될 때까지의 과도기 조치

#### 등록 시 크리에이터 작업
- 조형물을 촬영하여 가이드 이미지 제공 (유저에게 "이것을 찍으세요" 안내)
- 조형물의 특성 기술 (이름, 위치, 식별 포인트)
- 고수준 인증 도입 시: 복수 각도 촬영 + 특징점 디스크립터 추출

### 데이터 구조

```
스탬프 포인트 (서버 — Supabase DB)
  ├─ id
  ├─ lat, lng (등록 좌표)
  ├─ radius (판정 반경, 기본 500m)
  ├─ name (장소명)
  ├─ landmark_name (조형물 이름)
  ├─ guide_image (유저에게 보여줄 가이드 — "이것을 찍으세요")
  ├─ reward_asset_id → assets 테이블 참조 (콜라주 크리쳐/구조물)
  ├─ creator_id
  └─ created_at

유저 수집 기록 (서버 — Supabase DB)
  ├─ user_id
  ├─ stamp_id
  ├─ collected_at
  └─ (유저 좌표는 저장하지 않음)
```

### 보상 구조

스탬프 해제 시 유저가 받는 보상은 2층으로 구성된다.

**소유형 보상 — 수집 가능한 창작물**
- 콜라주 기반 크리쳐/구조물 (해당 장소의 환경 소재로 직접 제작)
- FeTreeOS 내 도감에 등록, 프로필 배지, 데스크탑 펫 배치
- 유저가 소유하는 디지털 자산 — 서비스와 무관하게 보존 가능 (유저 저장소)

**열람형 보상 — 잠금 해제 콘텐츠**
- 유튜브 일부공개(unlisted) 링크: 스탬프 해제 시에만 접근 가능
- 제작 과정 비하인드, 장소 스토리, 한정 영상 등
- 유튜브 인프라 활용 (호스팅 비용 0, 추천/검색 노출 없음)
- 유튜브의 유도 구조를 우회하면서 인프라만 사용하는 형태
- 향후 자체 호스팅 전환 가능 (링크 교체만으로 이행)

**설계 의도:**
- 물리적 이동이라는 동일한 열쇠로 두 가지 성격의 보상을 동시에 해제
- 소유형은 FeTreeOS 생태계 내 가치, 열람형은 콘텐츠 깊이 제공
- 유튜브 의존도: 열람형에 한정, 언제든 교체 가능한 구조로 유지

### 약도 — 인쇄 가능한 경로 안내

크리에이터가 직접 제작하는 손그림 약도. 네비게이션 앱 없이도 목적지에 도달할 수 있는 아날로그 가이드.

**형태:**
- 센트럴 → 목적지 경로를 시각화한 일러스트 맵
- 크리에이터의 콜라주/드로잉 스타일이 반영된 작품성 있는 약도
- 인쇄 가능 포맷 제공 (PDF / 고해상도 이미지)
- 유저가 출력해서 종이 한 장으로 이동하는 경험

**키프레임 표기 — 디지털 폴백:**
- 약도만으로 불충분한 구간에는 검색 가능한 참조점을 중간중간 표기
  - 주소 (도로명/지번)
  - 장소명 (검색 시 지도앱에서 찾을 수 있는 이름)
  - QR 코드 또는 짧은 코드 (스캔 시 해당 구간 상세 안내로 연결)
- 약도가 메인, 디지털 참조는 키프레임 — 전체를 앱에 의존하지 않되, 막히면 확인 가능

**커뮤니티 약도 — 인터렉티브 평원 형식 차용:**

인터렉티브 평원과 동일한 형식/조작을 빌려오되, 취지는 명확히 구분된다:

| | 인터렉티브 평원 (본편) | 커뮤니티 약도 (FeTreeGO!) |
|---|---|---|
| 성격 | r/place의 Drawn to Life — 추상화의 정점을 모두 함께 창조 | 실제 세계를 기반으로 함께 기록 |
| 대상 | 가상 세계 (빈 캔버스에서 출발) | 현실 장소 (물리적 경험에서 출발) |
| 방향 | 상상 → 창작 | 체험 → 기록 |
| 결과물 | 집단이 빚은 하나의 세계 | 집단이 쌓은 하나의 장소 기억 |

- 크리에이터가 초기 약도를 제공 (뼈대: 경로, 랜드마크, 키프레임)
- 유저들이 실제 방문 후 경험한 것을 기여:
  - 경로 위 발견물 (나무, 고양이, 벤치, 간판, 벽화, 계절 변화 등)
  - 체감 정보 ("여기 오르막 있음", "이 골목 그늘 좋음", "비 올 때 미끄러움")
  - 시각적 기여 (스케치, 사진 기반 픽셀아트, 콜라주 조각)
- 약도가 정적 이미지가 아닌 **살아있는 집단 지도**로 성장
- 시간이 지날수록 그 장소만의 기억이 층층이 쌓이는 구조
- **비지블 토글**: 커뮤니티 기여 레이어를 on/off — 순수 약도만 볼 수도, 모든 기여를 볼 수도 있음

형식과 조작은 공유하되, 하나는 추상을 창조하고 하나는 현실을 기록한다 — 같은 도구로 정반대 방향을 향하는 구조.

**데이터 주권 — 기여와 소유의 분리:**

기여한 스트로크/콘텐츠의 소유 구조:
- **유저 = 권리자**: 내가 그린 것은 내가 소유. 원본은 유저 저장소에 보존.
- **서버 = 수동적 보유**: 서버는 캔버스 합성을 위해 사본을 보유할 뿐, 권리를 주장하지 않음.

| | 유저 (권리자) | 서버 (수동적) |
|---|---|---|
| 원본 | 유저 저장소에 보존 (GitHub/Drive) | 합성용 사본 보유 |
| 권리 | 저작권, 사용권, 삭제 요청권 | 캔버스 표시 목적의 이용 허락만 |
| 서비스 소멸 시 | 원본 온전히 잔존 | 사본 소멸 |
| 철회 | 캔버스에서 제거 요청 가능 | 요청 시 삭제 의무 |

기여는 공유재로 보이지만, 소유는 빼앗기지 않는다. 서비스가 유저의 창작물에 대해 권리를 갖는 기존 플랫폼과 정반대 구조.

**서버의 관리권 — 모더레이션:**

"수동적"이 "무방비"를 의미하지는 않는다. 커뮤니티 환경 보호를 위한 최소한의 개입 권한은 서버에 있다.

dislike 누적 → 경고 및 완화 요청 → 제재(비활성화/삭제)

- 부적절한 표현(혐오, 음란, 폭력 등)에 대해 정당한 삭제/비활성화 권한 보유
- 즉시 삭제가 아닌 단계적 절차 — 유저에게 수정 기회 부여
- 제재 시에도 유저 저장소의 원본은 유저 소유로 잔존 (서버가 삭제하는 것은 캔버스상 사본)
- 기준은 커뮤니티 dislike(신고) 기반 — 운영자 독단이 아닌 집단 판단 우선

**철학적 의미:**
- 구글 맵 없이도 도달 가능한 구조 — 디지털 의존도 최소화
- 약도 자체가 수집 콘텐츠의 일부 (크리에이터 작품 → 커뮤니티 작품으로 확장)
- 종이를 들고 걷는 행위 = 화면에서 벗어나는 경험 그 자체
- 개방형 루트 원칙의 시각적 구현 — 안전 경로를 눈으로 보여주는 가장 직관적 방법
- "보잘것 없는 약도"가 커뮤니티의 손을 거쳐 그 장소만의 세계가 됨

## 안전 가이드라인

### 목적 선언

FeTreeGO!의 위치 기능은 **스탬프 판정(반경 내 존재 여부)**이라는 단일 목적으로만 사용된다.
추적, 프로파일링, 행동 분석, 광고 타겟팅 등 어떤 2차 목적으로도 사용하지 않는다.

### 광고 배제 및 상업적 중립

**광고 배제:**
- FeTreeGO! 내 어떤 콘텐츠에도 광고를 삽입하지 않는다 (배너, 인터스티셜, 스폰서, 네이티브 광고 일체)
- 위치 데이터, 수집 이력, 이동 패턴을 광고 목적으로 활용하지 않는다
- 수익 모델이 필요한 시점에도 광고가 아닌 다른 방식을 모색한다

**상업 시설 배제:**
- 스탬프 목적지 및 경유지에 식당, 상점, 카페 등 상업 시설을 채택하지 않는다
- 이유:
  - 상업 시설을 경유지로 두는 것 자체가 네이티브 광고와 구분 불가
  - 상점 폐업/이전 시 스탬프 무효화 (생명주기 리스크)
  - 가맹점 모델로의 변질 차단 (포켓몬 고 스폰서 포켓스탑 전례)
  - 특정 사업자에게 이익을 주는 구조는 공공성을 훼손
- 스탬프 대상: 공공 공간, 자연물, 공공 조형물, 문화재, 공원, 거리 예술 등 — 누구의 사업도 아닌 것들
- 단, 상업 시설이 있는 거리를 경로에서 배제한다는 의미가 아님 — 자연스러운 동선상 상가를 지나는 것은 정상이며, 인적 있는 구역으로서 오히려 안전한 경로일 수 있음
- 핵심: 특정 사업자의 이익을 의도적으로 보장하는 설계를 하지 않는다는 것. 프로젝트로 인해 주변 상권에 부수적 이익이 발생하는 것은 자연스러운 결과이며, 그것을 목적으로 설계하지 않을 뿐이다

### 유저 통제권

- **명시적 동의**: 최초 사용 시 위치 권한 요청 + 용도 설명 팝업
- **언제든 철회**: 브라우저 권한 해제 시 기능 비활성화, 패널티 없음
- **수집 기록 삭제**: 유저가 자신의 스탬프 수집 이력을 완전 삭제 가능
- **비로그인 사용**: 게스트도 판정 가능 (서버에 기록이 남지 않으므로)

### 미성년자 보호

- 위치 기능 자체가 좌표를 서버에 보내지 않으므로 미성년자의 위치가 시스템에 기록되지 않음
- 스탬프 포인트 등록 시 크리에이터 가이드라인:
  - 학교, 학원 등 미성년자 밀집 시설 반경 200m 이내 등록 금지
  - 유흥가, 위험 시설 인근 등록 금지
  - 야간에만 접근 가능한 장소 등록 금지
- 스탬프 포인트 신고 시스템: 부적절한 위치 등록에 대한 커뮤니티 리포트 → 검토 → 삭제

### 물리적 안전

- "이 장소에 가세요" 구조이므로 물리적 안전에 대한 책임 명시 필요:
  - 교통 위험 지역, 사유지, 출입 제한 구역에 스탬프 등록 불가
  - UX에 안전 고지: "스탬프 수집 중 발생하는 사고에 대해 서비스는 책임지지 않습니다. 안전한 경로를 이용하세요."
  - 크리에이터 등록 심사: 위험 장소 필터링 (고속도로변, 절벽, 공사장 등)
- 날씨/시간 경고 (선택적): 야간이나 악천후 시 "지금은 위험할 수 있습니다" 안내

### 개방형 루트 원칙

FeTreeGO!는 사람을 물리적으로 이동시키는 시스템이다. 단순한 콘텐츠가 아니다.
따라서 유저가 스탬프를 향해 이동할 때, **개방된 공간 — 시야가 확보되고, 인적이 있으며, 고립되지 않는 경로**를 보장하는 것은 설계자의 책임이다.

"개방형 루트"란 경로를 지정하지 않겠다는 의미가 아니라, **폐쇄적이고 고립된 동선으로 사람을 유인하는 구조가 되지 않도록** 경로의 안전성을 설계 단계에서 확보한다는 원칙이다.

#### 왜 이것이 필수인가

위치 기반 수집 시스템은 본질적으로 "이 장소에 가세요"라는 메시지를 던진다. 이것이 범죄에 악용될 수 있는 구조:
- 인적 없는 장소로 유인 → 강도, 폭행, 납치
- 미성년자를 고립된 동선으로 유도
- 야간/심야 시간대에 위험 지역으로 이동 유발

이를 구조적으로 차단하는 것이 개방형 루트 원칙의 목적이다.

#### 크리에이터의 책임

- 스탬프 포인트는 **개방된 공간에 위치해야 한다** — 골목 안쪽, 폐건물, 인적 없는 숲길 등은 부적격
- 등록 전 직접 걸어보고 확인: "여기까지 오는 동안 사람 눈이 있는가? 도움을 요청할 수 있는가?"
- 접근 경로상 시야 차단 구간(지하도, 긴 골목, 울타리 밀집 구간)이 불가피한 경우 해당 정보를 명시

#### 시스템의 책임

- **등록 심사 기준**: 스탬프 위치 및 주변 접근 경로의 개방성 평가
  - 주간 기준 보행자 통행량
  - CCTV/가로등 존재 여부
  - 대중교통 접근성 (정류장/역에서 도보 거리)
  - 주변 상가/주거 밀집도
- **안전 경로 제시**: 미성년자 및 취약계층이 이용할 가능성이 있는 스탬프에 대해 추천 경로를 제공
  - 인적이 드문 구간 회피
  - CCTV/조명 확보 구간 우선
  - 대중교통 연결 경로 안내
  - 야간 비권장 표기
- **위험 신고 대응**: 커뮤니티 리포트 → 검토 → 경고 라벨 또는 비활성화
- **시간대 경고**: 야간/심야에 해당 스탬프 접근 시 안전 주의 안내

#### 유저의 자율과 정보 제공의 균형

- 추천 경로는 **강제가 아닌 선택지** — 유저는 자신의 판단으로 다른 경로를 택할 수 있음
- 그러나 시스템은 알고 있는 위험 정보를 숨기지 않음
- "안전한 경로를 제시하되 강제하지 않는다" — 이것이 유도와 보호의 경계

#### 설계자의 자세

이 원칙은 면책 조항이 아니다. "사고 시 책임지지 않습니다"로 끝나는 것이 기존 플랫폼의 방식이라면, 이 프로젝트는 애초에 사고가 발생하기 어려운 구조를 설계하는 것을 목표로 한다. 사람을 움직이게 하는 시스템을 만드는 이상, 그 이동의 안전에 책임감을 가지고 임한다.

### 경로 설계 방법론 — 센트럴 우선 확보

#### 원칙

스탬프 포인트를 먼저 만드는 것이 아니라, **각 지역의 센트럴(중심 교통 거점)을 먼저 확보**하고, 거기서부터 목적지까지를 역산하는 순서로 설계한다.



#### 센트럴이란

각 광역시/도에서 대중교통 접근성이 가장 높은 거점. 예:
- KTX/SRT 역
- 시외/고속버스 터미널
- 지하철 주요 환승역
- 지역 대중교통 허브 (시내버스 집결지)

"어디서든 센트럴까지만 오면 스탬프에 접근 가능하다"는 보편적 접근성의 기반.

#### 초기 조사 우선순위

크리에이터가 1인이므로, 초기에는 스탬프 제작보다 **센트럴 조사가 선행**:

| 단계 | 작업 |
|------|------|
| 1 | 17개 광역시/도별 센트럴 후보 식별 |
| 2 | 각 센트럴의 대중교통 연결성 조사 (노선, 배차, 운행 시간) |
| 3 | 센트럴에서 도보 30분 이내 도달 가능한 개방 공간 맵핑 |
| 4 | 해당 공간에서 스탬프 포인트 후보 선정 |
| 5 | 직접 방문하여 안전성 + 소재(콜라주 원재료) 확인 후 등록 |

#### 현실적 제약과 AI 활용

- 1인 운영, 자차 없음, 도보 + 대중교통 기반
- 이 제약이 오히려 설계 품질을 보장함 — 크리에이터 본인이 대중교통 + 도보로 도달할 수 없는 곳은 유저도 도달하기 어려움
- 어디서 시작하든 방법론은 동일 — 시작 지역에 대한 제약 없음

**AI 활용 — 사전 조사/역산 단계:**
- 센트럴 후보 식별: 각 광역시/도의 교통 거점 데이터 수집 및 분석
- 경로 역산: 센트럴 → 후보 목적지 간 대중교통 연결성, 도보 구간 산출
- 안전성 사전 검증: 경로상 개방 공간 비율, CCTV/조명 분포, 보행자 통행량 추정
- 전국 동시 조사 가능 — 1인의 물리적 한계를 정보 수집 단계에서 해소

**직접 방문 — 최종 확인 단계:**
- AI 사전 검증을 통과한 후보지만 현장 방문
- 실제 체감 안전성 확인 (데이터에 없는 사각지대, 분위기, 인적 유무)
- 콜라주 소재 수집 (나뭇잎, 벽 질감, 이끼 등 — 이것은 현장에서만 가능)
- 조형물 참조 사진 촬영 (2단계 판정용)

| 법률/규정 | 대응 |
|-----------|------|
| 한국 위치정보법 | 위치정보 수집·이용 동의 (서버 미전송이므로 "수집" 해당 여부 검토 필요) |

### 법적 면책 및 윤리 가이드

#### 법적 면책 (창작자 보호)

법적 책임의 핵심: "예측 가능한 위험을 숨겼는가?" + "타인의 권리를 침해했는가?"

**지형지물 면책:**
- 앱/약도에 명시: "본 정보는 창작자의 기록 시점 기준이며, 실시간 현장 상황(기상, 공사 등)에 따라 위험이 발생할 수 있습니다. 이동 및 안전에 대한 최종 책임은 사용자 본인에게 있습니다"

**사유지 침범 금지:**
- 스탬프/크리쳐를 사유지 내부에 배치하지 않음
- "담벼락 밖에서 보이는 것"까지만 허용
- 안내: "사유지 무단침입 시 발생하는 법적 책임은 사용자에게 있습니다"

**초상권 및 저작권:**
- 크리쳐와 약도는 본인 저작물
- 타인의 얼굴, 특정 브랜드 로고가 약도/사진에 노출되지 않도록 처리

#### 윤리적 가이드 (지역 사회 공존)

법적 처벌이 아닌 "지속 가능한 환영"을 위한 장치.

**지역 비하 방지:**
- 특정 장소의 아픈 역사나 낙후된 이미지를 희화화하지 않는 디자인 품격 유지
- 인터뷰, 리서치 로그가 의도의 선의를 증명하는 근거

**주민 생활권 보호:**
- 야간 주거 밀집 지역 활동 자제 권고
- 소음 발생 가능 구역: "조용히 탐험해 주세요" 에티켓 안내

**도시락 에티켓:**
- 발생한 쓰레기를 반드시 되가져오는 것을 원칙으로, 콘텐츠에서도 이를 보여줌
- 지역 사회가 프로젝트를 지지하게 만드는 핵심 윤리

#### 현실적 타협점

모든 사고를 예방하려 하면 시작조차 할 수 없다. 다음 수준에서 타협:

- **긍정적 가이드**: "여기 위험하니 가지 마세요"가 아니라 "이 경로는 안전이 확인된 권장 경로입니다" — 권장 경로 밖 사고는 기획자 책임 영역이 아님
- **수정 가능성 인정**: "오류가 있을 수 있음"을 인정하고, 유저 제보로 즉시 수정하는 시스템 = 법적으로 "최선의 노력"을 증명하는 근거
- **한 줄 요약**: 안내문에 경고 문구 명시(법적) + 주민 사유지 침범하지 않는 선에서 긍정적 지역 요소를 디자인(윤리) → 프로젝트 성립에 문제 없음

### 악용 방지 구조

- **역추적 불가**: 수집 기록에 좌표가 없으므로 "이 유저가 언제 어디에 있었는지" 추론 불가
  - 스탬프 ID로 장소를 유추할 수는 있으나, "그 시각에 그 장소에 있었다"는 수준 — 이마저도 collected_at 정밀도를 일(day) 단위로 낮추면 완화
- **스토킹 방지**: 타인의 수집 현황은 본인 공개 설정에 따름 (기본: 비공개)
- **스탬프 밀집 방지**: 같은 구역에 과다 등록 시 특정 루트를 강제하는 효과 → 최소 간격(예: 500m) 제한
- **크리에이터 신원 확인**: 스탬프 등록자는 인증된 계정만 가능 (부적절 등록 시 책임 추적)

## 디지털 탐험 — Digital-First 확장

### 철학적 동치

FeTreeGO!의 핵심 원리는 '직접 해보지 않으면 알 수 없는 것(혹은 의미가 없는 것)'에 가치를 부여하는 것이다. 이 원리는 물리적 장소에 국한되지 않는다.

| 물리적 탐험 | 디지털 탐험 |
|------------|------------|
| 그 장소에 가야만 볼 수 있는 것 | 그 페이지/앱/OS에 들어가야만 알 수 있는 것 |
| 걸어서 도달하는 행위 | 탐색하고 찾아내는 행위 |
| 현장 환경이 크리쳐를 만듦 | 디지털 환경이 발견물을 만듦 |
| GPS가 가이드 | 힌트/단서가 가이드 |

**공통 원칙: 행동 수행에 가치를 부여한다.**
- 누군가 알려줘서 아는 것 ≠ 직접 가서(찾아서) 확인한 것
- 검색으로 답을 얻는 것 ≠ 직접 탐험하며 발견하는 것
- 스크린샷을 보는 것 ≠ 직접 그 환경에서 경험하는 것

### 디지털 탐험이란

다양한 디지털 공간(웹사이트, 앱, OS, 플랫폼, 숨겨진 페이지, 인터페이스)을 돌아다니며 직접 확인하고, 거기에 무엇이 있는지를 알아내는 행위.

**탐험 대상 예시:**
- 웹사이트의 숨겨진 페이지, 이스터에그
- 앱/OS의 특정 경로나 설정 조합으로만 도달하는 화면
- 특정 조건(시간, 순서, 입력)을 충족해야 나타나는 콘텐츠
- 플랫폼 간 연결점 — A에서 힌트를 얻어야 B에서 발견 가능
- API 응답, 소스 코드 내 주석, 메타데이터 속 단서

### 인증 구조 — 디지털 행동 증명

물리적 탐험의 "거기 가서만 볼 수 있는 것"에 대응하는 디지털 등가물:

| 물리적 인증 | 디지털 인증 |
|------------|------------|
| 현장에서만 확인 가능한 조형물 디테일 | 해당 환경에서만 확인 가능한 정보 |
| GPS 반경 진입 (가이드) | 특정 URL/경로 도달 (가이드) |
| 사진 EXIF (보조) | 스크린샷/상호작용 증거 (보조) |
| 콘텐츠 구조가 방어 장치 | 탐험 과정 자체가 방어 장치 |

**핵심**: 답을 검색으로 찾을 수 있더라도, 직접 탐험하는 과정에서 얻는 맥락과 경험은 대체 불가능. 시스템은 "답"이 아닌 "과정"을 인증한다.

### 물리적 탐험과의 연결점 (아날로그 ↔ 디지털)

디지털 탐험 시스템이 선행하면, 아날로그로의 확장이 자연스럽게 열린다:

**디지털 → 아날로그:**
- 디지털 스탬프 중 일부: "이 스탬프의 원본을 보려면 실제로 그곳에 가라"
- 온라인 탐험에서 얻은 단서가 물리적 장소를 가리킴
- 디지털 약도 완성 → 인쇄하여 현장 탐험의 가이드로 사용

**아날로그 → 디지털:**
- 현장 방문 시 QR/NFC → FeTreeOS 내 숨겨진 디지털 공간 해제
- 물리적 각인(스탬프) → 디지털 도감에 프리미엄 마크 부여
- 현장에서만 볼 수 있는 코드 → 온라인 콘텐츠 잠금 해제

**혼합형:**
- 특정 장소에서 + 특정 앱/웹을 열어야만 보이는 AR적 콘텐츠 (기술적 AR이 아닌 조건 조합)
- 디지털 탐험 완주자에게만 물리적 스탬프 위치 힌트 제공
- 계절/시간 + 물리적 위치 + 디지털 조건의 다중 조합

### Digital-First의 전략적 이점

| 항목 | 내용 |
|------|------|
| 초기 비용 | 거의 0 (각인기, 설치 협의 불필요) |
| 스팟 추가/변경 | 즉시 가능 — 물리적 제약 없음 |
| 지역 제약 | 없음 — 한국에서 시작, 일본/전세계 동시 가능 |
| 실험 속도 | 빠름 — 콘텐츠 구조 A/B 테스트 용이 |
| 플랫폼 검증 | 디지털로 핵심 루프(탐험→발견→수집) 검증 후 물리적 확장 |
| 콘텐츠 생산 | 1인으로 다수 스팟 동시 운영 가능 |
| 유저 접근성 | 이동 불가 유저도 동등 참여 (트랙 B의 상위 호환) |

### 물리적 각인의 위치 재정의

Digital-First 구조에서 물리적 각인(스탬프 머신, 현장 설치)은:
- 초기 필수 요소가 아닌 **프리미엄 경험 레이어**
- 디지털 탐험 + 물리적 방문을 모두 완수한 사람에게 주어지는 최종 보상
- 수익화 이후, 파트너십 기반으로 확장하는 단계

### 구현 우선순위

| 단계 | 내용 | 비고 |
|------|------|------|
| 1 | 디지털 탐험 코어 루프 | 탐험→발견→인증→수집 |
| 2 | FeTreeOS 내 도감/프로필 연동 | 수집 시 OS 환경 변화 |

### 별자리 보상 시스템 (Constellation Reward)

**아이디어**: 스탬프를 전부 모으면, 맵 위의 스탬프 좌표들을 이어 하나의 별자리 형태가 드러난다.

**철학적 일치**:
- 수집 과정에서는 흩어진 점 — 전체상을 알 수 없음
- 완주하는 순간 선이 이어지며 형태 출현 — '직접 다 해봐야 비로소 보이는 것'
- 부분으로는 의미 없고, 전체를 모아야 비로소 의미가 생기는 구조

**확장 가능성**:
- 지역마다 다른 별자리 (별자리 = 스탬프 세트 단위)
- 별자리 도감 수집 (메타 수집 레이어)
- 어떤 별자리인지는 미리 알 수 없음 — 완성해야 형태 드러남
- 별자리 형태 자체가 힌트 (다음 지역이나 숨겨진 스탬프를 가리킴)
- 여러 별자리를 모으면 더 큰 성좌도(star chart)가 완성되는 계층 구조

**기술적 구현**:
- 스탬프 좌표 배치 자체를 별자리 형태에 맞춰 설계 (역방향: 별자리 → 좌표 배정)
- 완주 시 SVG/Canvas로 선 연결 애니메이션
- 미수집 시에는 별자리 형태 노출 없음 (좌표 배치의 의도를 숨김)
