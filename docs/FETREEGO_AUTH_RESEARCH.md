# FeTreeGO! — 디지털 탐험 인증 방법론 연구

## 핵심 원칙

**"자신이 무언가에 물리적 행위를 동반하여 도달하는 것"**

디지털이든 아날로그든, 핵심은 동일하다:
- 직접 이동해야만 알 수 있는 것
- 직접 행동해야만 도달하는 것
- 누군가에게 들어서는 의미가 없는 것

"밖"은 물리적 장소일 수도, 디지털 공간일 수도 있다:
- 바탕화면
- 유튜브 (직접 '검색'하여 도달 — 검색 행위 자체가 물리적)
- 구글 검색 결과
- 어떤 웹사이트의 특정 위치 (스크롤 끝, 숨겨진 페이지)
- 앱/OS의 특정 경로

**가치의 원천**: 하나하나는 미미할 수 있으나, 누적되는 복리의 변화. 작은 행동의 축적이 사람을 바꾼다.

---

## 시스템 구조

```
[맵] ──힌트/가이드──→ [밖의 공간] ──관찰──→ [맵으로 돌아와 인증]
 │                      │                        │
 안내판                물리적 행동               퀴즈 입력
 (디지털)              (플랫폼 밖)              (디지털)
```

맵은 안내판이다. 목적지가 아니다.
모험가는 지도만 보면서 다니지 않는다.

## 인증의 주체: 퀴즈 (플랫폼 무관)

"거기에 가서 뭐가 있었는지 적어봐"

### 구체적 예시

| 밖의 공간 | 물리적 행동 | 퀴즈 |
|----------|------------|------|
| 어떤 웹사이트 | 스크롤을 끝까지 내린다 | "가장 아래에 보이는 것은?" |
| 유튜브 | 특정 키워드로 검색한다 | "첫 번째 영상의 제목은?" |
| 바탕화면 (FeTreeOS) | 특정 폴더를 열어본다 | "그 안에 있는 파일 이름은?" |
| 구글 검색 | 힌트 단어를 검색한다 | "세 번째 결과의 사이트 이름은?" |
| 실제 장소 | 그곳에 가서 본다 | "간판 옆에 그려진 그림은?" |
| 다른 앱/서비스 | 접속하여 확인한다 | "프로필 페이지 하단에 적힌 문구는?" |

### 특성

- 답은 "거기에 가서 직접 확인한 사람"만 알 수 있다
- 검색으로 찾을 수도 있지만, **검색 행위 자체가 이미 물리적 행동**
- 기술적 제약 제로 — 어떤 기기, 어떤 브라우저에서든 인증 가능
- 정적 콘텐츠로 구현 가능 (서버 불필요)

### 미해결 과제

- 답이 시간에 따라 변하는 콘텐츠(유튜브 검색 결과 등)는 정답 유지 관리 필요
- 스포일러 공유 시 무력화 가능성 — 단, GEOSTAMP와 동일 논리로:
  - "속이는 비용 > 직접 하는 비용"이면 충분
  - 답을 알아도 직접 해본 경험의 가치는 소멸하지 않음
- 퀴즈 형태: 주관식(자유 입력) vs 객관식 — 검증 용이성과 경험 깊이의 균형

## API의 역할: 컨트롤러 (조미료)

API는 인증의 주체가 아니라, **밖의 공간에서 행동을 유도하고 풍부하게 하는 도구**.

### 울타리 vs 컨트롤러

| 잘못된 사용 (울타리/가두리) | 올바른 사용 (컨트롤러) |
|---------------------------|----------------------|
| "다크모드로 전환하면 스탬프 획득" | "그 장소에서 북쪽을 향하면 보이는 것은?" (방향 감지가 행동을 유도) |
| "DevTools 열면 답이 보임" | "이 페이지에서 10초 기다리면 나타나는 문구를 적어라" (시간이 경험을 만듦) |
| 특정 브라우저에서만 작동 | 어떤 기기에서든 가능, API는 경험을 풍부하게 할 뿐 |

### 컨트롤러로서의 API 활용 예시

- **방향/기울기**: 현장에서 특정 방향을 보게 유도 → 보이는 것을 퀴즈로 인증
- **시간**: 특정 시간대에만 나타나는 콘텐츠 → 그것을 관찰하여 보고
- **위치(GPS)**: 탐색 가이드로만 사용 (GEOSTAMP 기존 설계와 동일 — 인증 수단 아님)
- **카메라**: 현장에서 촬영 유도 → EXIF 메타데이터가 보조 증거 (강제 아님)
- **소리**: 특정 소리를 듣게 유도 → 무엇이 들렸는지 보고

**핵심**: API가 없어도 인증은 가능하다. API가 있으면 경험이 풍부해질 뿐.

## "밖"의 범위 — 디지털도 물리적이다

"디지털 공간으로의 이동"도 물리적 행위이다:
- 검색창에 타이핑하는 것
- 스크롤을 내리는 것
- URL을 입력하고 엔터를 누르는 것
- 앱을 전환하는 것

이 행위들은 "누군가 알려줘서 아는 것"과 구별된다.
직접 검색하여 도달하는 것은 — 흔하지 않은, 꽤 물리적인 행위.

### 디지털 "밖"의 예시

| 공간 | 행동의 물리성 |
|------|-------------|
| 유튜브 | 키워드를 생각하고, 타이핑하고, 결과를 눈으로 확인 |
| 웹사이트 | URL을 입력하거나 링크를 따라가고, 페이지를 탐색 |
| FeTreeOS 바탕화면 | 폴더를 열고, 파일을 찾고, 실행해서 확인 |
| 구글 검색 | 질문을 구성하고, 결과를 읽고, 판단 |
| 다른 앱 | 전환하고, 탐색하고, 특정 지점에 도달 |

모두 "손을 움직여 도달해야만 아는 것"이다.

## 가치 구조 — 복리의 누적

개별 스탬프 하나는 사소할 수 있다.
하지만 설계 의도는 단일 행동의 보상이 아니라 **행동 습관의 형성**:

- 작은 탐험의 반복 → "직접 확인하는 습관"
- 누적 → 세계에 대한 감각 변화
- 별자리 보상: 전체를 모아야 비로소 드러나는 형태 = 복리의 시각화

"작은 것을 무시하지 않는 사람"에게 보이는 것이 있다.

## 프로토타입과의 관계

현재 fetreego/ 프로토타입:
- 맵 UI (팬/줌) → 유지 — 안내판 역할
- 스탬프 마커 + 팝업 → 유지 — 힌트/퀴즈 전달 인터페이스
- 인증 방식 → 수정 필요: API 트릭 → 퀴즈 입력 (밖에서 관찰한 결과)
- 별자리 보상 → 추가 예정: 전부 모으면 좌표 연결

## 미해결 핵심 질문

1. **정답 관리**: 밖의 콘텐츠가 변하면(유튜브 검색 결과, 사이트 업데이트) 정답도 변해야 하는가? → 변하지 않는 대상을 선별하는 것이 설계자의 역할?
2. **스포일러**: 답이 공유되어도 "직접 해봐야 의미 있는" 구조를 어떻게 보장하는가?
3. **난이도 곡선**: 너무 쉬우면 검색으로 끝, 너무 어려우면 포기 — 적정선은?
4. **정적 검증**: 서버 없이 정답 비교를 안전하게 하는 방법 (해시? 클라이언트 측 충분?)
5. **콘텐츠 설계**: 어떤 "밖"을 탐험시킬 것인가 — 크리에이터의 핵심 역할
