# FeTreeGO! — 현실성 및 우려사항 점검

## 기술적 현실성

| 항목 | 상태 | 비고 |
|------|------|------|
| GPS 1회 판정 | 즉시 가능 | 탐색 가이드 용도 (인증 수단 아님) |
| 현장 전용 인증 | 콘텐츠 구조로 해결 | 기술적 부하 없음 — "거기서만 알 수 있는 것" 요구 |
| 사진 휴리스틱 (EXIF 등) | 브라우저 API로 충분 | 성능 부담 없음 |
| 벡터 스트로크 유저 저장소 분산 | 설계 가능 | GitHub API rate limit, OAuth 이탈률 — 현 단계에서 먼 이야기 |
| 인터렉티브 평원 연동 약도 | 본편이 먼저 완성되어야 함 | 의존 순서 |
| 인쇄용 약도 PDF 생성 | 단순 | 크리에이터 제작 공수 |

**해소된 우려:**
- ~~ORB/OpenCV.js 모바일 성능~~ → 저수준 인증 채택으로 불필요. 고수준 인증은 선택적 옵션으로 격하.
- ~~GPS 반응성~~ → GPS는 탐색 가이드일 뿐, 반응성 자체가 치명적이지 않음.

## 운영적 우려

| 항목 | 우려 | 완화 방안 |
|------|------|-----------|
| 1인 센트럴 조사 | 현장 검증은 시간/비용 | AI 사전 역산 + 직접 방문은 최종 확인만 |
| 스탬프 품질 관리 | 초기 본인만 등록 → 통제 가능 | 커뮤니티 개방 시 등록 심사 + dislike |
| 모더레이션 인력 | 1인 처리 한계 | 초기 규모 가능, 확장 시 관리자 위임 |
| 조형물 변경/철거 | 스탬프 무효화 | 커뮤니티 제보 (포맷: 어디가 + 어떻게 달라졌는가) → 신속 대응 |

**해소된 우려:**
- ~~커뮤니티 약도 품질~~ → 비주얼 기여(인터렉티브 평원 형식)이므로 안전 정보 부정확 문제 없음. 잉크게이지로 스팸 차단 + dislike 모더레이션.

## 법적/책임 우려

| 항목 | 우려 | 현재 대응 |
|------|------|-----------|
| 이동 중 사고 | 책임 소재 논쟁 | 면책 문구 + 개방형 루트 + 위험지 금지 + 긍정적 가이드 방식 |
| 위치정보법 | 클라이언트 전용이라도 "수집" 여부 | 보수적 동의 취득 |
| 미성년자 사고 | 가장 치명적 | 학교 인근 금지, 야간 경고, 안전 경로, 개방 공간 원칙 |
| 스토킹 도구화 | 수집 이력에서 위치 추론 | collected_at 정밀도 제한 + 기본 비공개 |
| 사유지 침범 | 스탬프가 사유지 내부 유도 | 담벼락 밖까지만 허용, 안내 문구 명시 |
| 초상권/저작권 | 약도/사진에 타인 얼굴, 브랜드 노출 | 노출 방지 처리 원칙 |

**법적 자문 시점:** 면책 문구와 가이드를 적었으나 법적 효력은 전문가 검토 필요. 서비스 공개 전 최소 1회 자문 권장.

## 해소된 주요 리스크

### ~~OpenCV.js 모바일 체감~~ → 해소
저수준 인증(GPS 가이드 + 현장 전용 인증 + EXIF 휴리스틱) 채택으로 무거운 라이브러리 불필요.

### ~~GPS 스푸핑~~ → 구조적 해소
"거기를 갔다오지 않고서는 할 수 없는 것을 요구한다" — 콘텐츠 구조 자체가 방어 장치. GPS를 속여도 현장 경험 없이는 의미 있는 참여 불가능.

## 남은 리스크

### ~~1. 미성년자 안전 사고~~ → 현실적 대응 완료

예방 구조 + 면책이 이미 확보됨:
- 개방형 루트 원칙 (폐쇄 공간 배제)
- 학교/학원 인근 200m 등록 금지
- 야간 경고, 안전 경로 제시
- 사유지 침범 금지
- 면책 문구 + 윤리 가이드 + 법적 면책 조항

1인 프로젝트가 할 수 있는 현실적 범위에서 예방과 면책 모두 갖춤. 완벽 방지는 어떤 서비스도 불가능하며, 현재 설계가 상식적 선을 충분히 확보.

### ~~2. 초기 콘텐츠 부재~~ → 구조적 해소

닭/달걀 문제가 아님 — 유튜브 영상 콘텐츠가 선행하고, 스탬프는 그 연장선에서 쌓이는 구조:
- 장소 탐방 + 크리쳐 제작 영상 (콘텐츠 퍼널 입구) → 해당 장소에 스탬프 등록
- 영상을 본 사람이 직접 가보는 동기 발생
- 전 지역에 꾸준히 누적 — 급하게 채울 필요 없음, 콘텐츠 제작과 함께 자연 증가

### ~~3. 접근성 형평성~~ → 대체 참여 구조로 해소

물리적 이동이 본질인 시스템에서 이동 약자의 참여 장벽 문제.

**현실적 포용 범위 (잠정):**
- 휠체어/유모차 이용자 — 경사, 계단, 포장 상태 표기
- 시각 약자 — 앱 접근성(스크린리더, 고대비), 현장은 동행자 전제
- 고령자 — 난이도 표기, 센트럴 근처 스탬프 활용
- 대중교통 의존자 — 센트럴 설계가 이미 커버

**선을 긋는 지점:**
- 이 프로젝트는 "바깥에 나가서 걷는" 시스템. 물리적 이동이 본질이며 이를 포기하면 성립하지 않음
- 모든 장소를 모든 사람이 접근 가능하게 만드는 것은 물리적으로 불가능
- 할 수 있는 것: 접근성을 보장하는 것이 아니라 **접근성 정보를 보장**하는 것 — "이 스탬프는 이런 접근 조건이다"를 명확히 알려서 본인이 판단 가능하게

**하한 전제:**
- 자력으로 해당 콘텐츠의 유무를 식별할 수 있는 사람
- 콘텐츠의 존재를 모르는 사람은 포용 대상이 될 수 없음 — 이것은 논리적 전제
- 이 전제 위에서 물리적 이동 가능 여부에 따라 참여 형태가 달라지는 구조

**이동 불가능한 유저에 대한 설계 의지:**
- "배려해서 쉽게 해준다"가 아니라, 물리적 이동과 **동일한 무게의 노력을 다른 형태로** 요구한다
- 이동하는 사람과 동등한 참여, 동등한 보상 — 형태만 다를 뿐
- 구체적 방법은 미정. 답이 떠오를 때 채운다.

**대체 참여 구조 (확정):**

장소 기반 비주얼 노벨 + 미니게임 — 이동의 디지털 치환:
- 크리에이터가 걸은 실제 경로를 스테이지로 구성
- 각 스테이지가 unlisted 링크로 연쇄 — 미니게임 돌파 시 다음 장소의 링크 해제
- 이동자의 "걷기"를 플레이어의 미니게임 내 물리적 행위(조작, 탐색, 퍼즐)로 치환
- 한 스테이지를 건너뛸 수 없음 = 걸어야 다음 지점에 도달하는 것과 동일
- 약도가 미완성 상태로 제공 → 스테이지 진행 + 퀴즈로 약도를 완성
- 완주 시 동일한 보상 획득

노력 동등성:
- 이동자: 물리적으로 걸어서 경로를 따라 도달
- 디지털 참여자: 미니게임의 물리적 행위로 같은 경로를 돌파
- 형태는 다르지만 둘 다 "성의 없이는 도달 못 하는" 구조
- 건너뛰기 불가 — 연쇄 unlisted 링크가 순서를 강제

도착점의 동등성:
- 이동자: 현장에서 약도에 비주얼 기여 → 약도 로그 참여자
- 디지털 참여자: 비주얼 노벨 완주 → 약도 완성 → 약도 로그 참여자
- 경로가 다를 뿐, 도착점은 동일 — 둘 다 약도의 기여자로 남는다

### ~~4. 수익 모델 부재~~ → 의도적 설계

- 제로 달러 모델 — 돈에 굴하지 않는 프로젝트로 진행
- 광고 배제, 상업 시설 배제는 철학적 선택이지 리스크가 아님
- Supabase 무료 티어 + 유저 저장소 분산으로 비용 구조 이미 최소화
- 수익이 아닌 지속 가능성으로 접근 — 비용을 낮추는 설계가 곧 생존 전략

### ~~5. 날씨/계절 의존성~~ → 설계 + 제보로 해소

- 크리에이터가 애초에 계절/날씨에 영향받지 않는 대상을 찾아서 설정
- 예상 밖 이벤트 (폭설, 태풍, 파손 등)로 인증 대상이 무효화된 경우 → 제보 시스템으로 대응
- 유저 활동 급감(폭염, 한파, 장마)은 서비스 문제가 아닌 자연 현상 — 강제하지 않으므로 리스크가 아님
